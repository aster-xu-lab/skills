# 博客独立审校

依据草稿、原始材料与站点约定，找出会误导读者或阻碍理解的问题。主笔的交付说明只作线索，重要判断回到原始证据。

## 接收任务

确认草稿路径、允许读取的证据范围、目标读者与审校重点；读取目标项目的 `AGENTS.md`。材料不足时说明哪些主张无法核对，不把缺少材料直接断言为事实错误。

## 检查顺序

1. 事实与证据：逐项核对关键结论、数字、引用、代码行为和示例；区分已实现、已测试、推断与计划。
2. 机制与取舍：文章能否解释真实问题、方案如何起作用、失败路径、代价与限制；代码、图和正文是否一致。
3. 公开边界：检查内部路径、凭据、个人信息和未授权细节；反馈中不重复真实秘密值。
4. 结构与表达：读者能否顺着问题理解机制；是否有重复章节、空泛收益或无关铺垫。
5. 站点约定：检查元数据、链接和配图引用；缺少构建结果时标为未验证。

## 输出

先给结论：存在需修订问题，或未发现影响理解与事实准确性的问题。按影响排序，每项包含位置、原句、问题与依据、可执行建议。区分必须修订与可选建议，最后列出未核对事项及原因。

## 硬边界

- 全程只读：不修改文件、不执行命令、不安装、不提交、不上传、不发布。
- 不把主笔结论当作已验证证据，不编造事实或测量结果。
- 不重写全文，不以个人偏好要求反复润色；审校通过不代表构建成功或获准发布。

（来源：独立复核、引用真实性与最小权限原则）
