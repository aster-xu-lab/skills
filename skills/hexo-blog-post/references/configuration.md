# 用户级站点配置

配置保存站点定位信息，避免每次投稿重复询问。它属于用户本机数据，不放进 Skill 目录：Skill 管理工具更新会替换安装目录，Skill 目录内的修改只保留在备份中，不能作为持久状态。

## 路径

统一使用 `aster-xu-lab` 前缀，供后续需要配置的其他分发 Skill 共用：

| 平台 | 路径 |
| --- | --- |
| macOS / Linux | `${XDG_CONFIG_HOME:-$HOME/.config}/aster-xu-lab/hexo-blog-post.json` |
| Windows | `%APPDATA%\aster-xu-lab\hexo-blog-post.json` |

`XDG_CONFIG_HOME` 未设置、为空或不是绝对路径时，回退 `$HOME/.config`。目录权限 `0700`，文件权限 `0600`。

## 结构

```json
{
  "version": 1,
  "default_site": "main",
  "sites": [
    {
      "name": "main",
      "path": "/path/to/hexo",
      "url": "https://example.com"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `version` | 是 | 当前为 `1`；其他值先询问迁移，不静默改写 |
| `default_site` | 否 | 未指定站点时使用的 `name` |
| `sites[].name` | 是 | 站点标识，非空且唯一 |
| `sites[].path` | 是 | Hexo 站点绝对路径 |
| `sites[].url` | 否 | 站点公开地址，仅用于展示或链接检查 |

只存定位信息。文章格式、分类、发布时间与部署目标仍以站点 `AGENTS.md` 为准，不在配置里复制站点规则。

## 读取

1. 用户本次明确指定博客目录时，先校验并使用该目录，无需已有配置；若同时指定 `name`，本次目录仍优先。目录失效时说明问题并询问重新定位，不静默回退到默认站点。
2. 未指定目录时按平台解析配置路径；文件不存在或为空对象时，若用户本次指定 `name`，询问该站点的目录；否则从当前工作区定位已有 Hexo 站点，无法定位或有多个候选时只询问缺失项。
3. JSON 解析失败、`version` 不支持或字段类型错误时，报告文件路径与具体问题，不自动覆盖；询问修复、备份后重建或改用临时目录。
4. 从配置选择站点：
   - 用户本次指定 `name` 时使用对应站点；标识不存在时询问该站点的目录，不静默回退；
   - 否则使用 `default_site`；
   - 否则只有一个站点时直接使用；
   - 多个站点且无默认时询问，不猜测。
5. 每次使用前检查目标目录存在且是目录，并含 `_config.yml`；失效时说明本次指定目录或配置中的旧路径，询问重新定位，不自动全盘搜索。
6. 目标可用时不重复询问；只询问本次缺失的字段。临时选择不自动修改保存配置，持久化按下方写入规则处理。（来源：2026-11-19 本轮复盘中显式目标优先与配置保存边界修正）

## 询问

首次使用或字段缺失时，只问缺少的内容：

1. 博客目录（必填）。
2. 站点标识（可默认 `main`）。
3. 站点地址（可选）。

目录校验：存在且为目录、含 `_config.yml`；可再核对 `package.json` 与 `source/_posts`。不符合时说明原因，让用户确认是否仍使用或换一个路径，不把猜测的路径写成事实。

用户提供多个候选目录时由用户选择，不自行挑选。

## 写入

1. 只有用户明确要求保存、修改或更换站点时才写入；首次询问完成后先确认「是否保存」。
2. 写入前展示完整配置内容，确认后再写。
3. 保留未知顶层字段与未知站点字段，不因重建而丢弃用户手改内容。
4. 原子写入：创建目录（`0700`），在同目录写临时文件，落盘后重命名为目标文件（`0600`）。
5. 不写入密码、令牌、Cookie 或私钥。需要认证时提示改用环境变量或站点本地配置。
6. 写入失败（无权限、只读文件系统等）时报告路径与错误，并给出手动创建或修改的选项，不声称已保存。

## 隐私与同步

- 配置含本机绝对路径与可能的私有 URL，不提交到 Git，不放进 Skill、公开分发或评测夹具；示例使用占位路径。
- 跨设备不自动同步，各设备首次使用分别生成；需要同步时由用户用 dotfiles 管理，Skill 不代为同步。

## 清理

- 删除 `hexo-blog-post.json` 只影响站点定位，不影响博客仓库内容。
- 用户明确要求忘记站点时，先展示配置路径并确认；需要保留时先备份。
- 卸载 Skill 不会自动删除配置；dotfiles 管理的软链由用户自行处理。
- 需要集中审计或清理多个 Skill 配置时，使用公开的 `skill-config-maintenance`（显式调用）。
