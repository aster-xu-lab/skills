# Java/Spring 与桌面产物的差异

本文件只列交付链上的差异点；具体命令、插件与平台细节以目标项目为准。

## Java/Spring 服务

| 环节 | 检查点 |
| --- | --- |
| 构建 | Maven/Gradle 版本、JDK 版本、依赖锁定、多模块顺序 |
| 测试 | 单元、切片、集成；Testcontainers 或项目既有方式 |
| 制品 | 可执行 jar、容器镜像或多模块产物；版本来自构建元数据 |
| 配置 | Spring profile / 环境变量 / 配置中心；密钥不入包 |
| 启动 | 健康检查、端口、依赖连通性、迁移是否执行 |
| 迁移 | Flyway/Liquibase 版本顺序；向前兼容与回滚限制 |
| 观测 | 日志、指标、追踪、发布标识 |

注意：

- 多模块项目要确认构建顺序与共享模块版本。
- 容器镜像使用多阶段构建，运行层不含构建工具与源码。
- Spring Boot 的配置文件按环境注入，不把生产配置打进镜像。
- 集成测试使用真实数据库引擎，不用兼容模式替代锁与事务语义。
- 数据库迁移与应用发布分开记录；迁移失败时应用不应继续启动。

## 桌面产物

桌面打包、签名、公证、安装、自动更新与版本 feed 的细节走 `desktop-release`。本 Skill 只关心交付链上的共同部分：

- 平台与架构矩阵（macOS/Windows，x64/arm64）。
- 产物版本与渠道标识来自真实元数据。
- 构建环境可复现，原生依赖与侧车资源匹配目标平台。
- 制品上传与 feed 激活分开授权。
- 安装、启动、核心能力、更新升级分别验证。

## 两者共同的交付门禁

1. 同一提交、同一版本只产出一套可追溯制品。
2. 配置与密钥不进入制品。
3. 发布前有成功判据与回滚方式。
4. 构建、安装、启动、流量/使用分别记录状态。
5. 未覆盖的平台或环境明确列出。

## 常见坑

- Java 多模块只构建了部分模块，制品缺依赖。
- 镜像里打进了测试配置或本地路径。
- 桌面端只验证一个平台，另一个平台靠推断。
- 桌面更新 feed 指向错误渠道或旧版本。
- 把 jar 启动成功当成服务可用；没有检查依赖与迁移。
- 把桌面包生成成功当成安装与自动更新成功。
