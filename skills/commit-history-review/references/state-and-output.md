# 续审状态与输出细则

## 外置配置

路径按本 Skill 的外置配置约定：

- macOS / Linux：`${XDG_CONFIG_HOME:-$HOME/.config}/aster-xu-lab/commit-history-review.json`
- Windows：`%APPDATA%\aster-xu-lab\commit-history-review.json`

最小结构：

```json
{
  "version": 1,
  "repos": {
    "/absolute/path/to/repo": {
      "last_reviewed_commit": "<40 位 sha>",
      "last_reviewed_at": "2026-11-24T10:00:00+08:00",
      "last_range": "<base>..<head>"
    }
  }
}
```

规则：

- 只在增量模式且用户同意后写入；首次缺失字段只询问缺失项。
- 以 `git rev-parse --show-toplevel` 的绝对路径为键；使用前校验路径仍存在，失效时重新询问。
- 保留未知字段；原子写入；文件权限 `0600`。
- 不写 diff、提交正文、完整报告、密钥、令牌或内网地址。
- 配置属于本机用户数据，不提交到 Git，不进入评测夹具、示例或公开分发。
- 跨设备分别生成；需要同步时由用户自行管理，Skill 不代为同步。
- 清理：用户明确要求忘记基线时，删除 `commit-history-review.json`；先展示路径并确认，需要保留时先备份。删除后下次增量审查重新指定基线。
- 需要集中审计或清理多个 Skill 配置时，使用公开的 `skill-config-maintenance`（显式调用）。

读取失败、JSON 损坏或基线 commit 在当前仓库不存在时，不静默重置；报告问题并请用户指定新的基线。

## 输出细则

### 审查快照

必须放在最前。复核脚本依赖这个位置与字段名：

- 仓库：绝对路径。
- HEAD：完整或短 SHA + 分支。
- 审查范围：窗口、增量或单提交。
- 提交数：实际 `git log --oneline` 条数。
- 工作区：clean / dirty。
- 未提交文件：逐项列出；无则写「无」。
- 行号口径：提交 / 工作区。
- 验证命令：实际执行过的命令与结果；未执行写「未执行」。

### 逐提交发现

按严重度排序；同一提交内按文件排序。每条包含：

- 严重度：P0–P3；无证据写“待确认”。
- 提交：短 SHA + 提交标题。
- 位置：`path:line`，并说明锚定提交。
- 问题：一句可复核的描述。
- 证据：diff 片段、调用方、测试缺失或可复现命令。
- 建议：最小修复方向；不写完整补丁，除非用户要求。

### 聚合评估

- 反复出现的问题与热点。
- 与上次审查相比的已修复/仍存在/新出现；没有基线时明确写“无上次报告可比”。
- 测试、文档、迁移的滞后情况。
- 质量趋势：仅在有足够提交样本时给判断；样本不足写“样本不足”。

### 启示

区分：

- 事实：从 diff、提交、测试、配置直接读到。
- 推断：可能的原因或风险，标注“推断”。
- 建议：是否值得更新项目约定、测试门禁、提交规范或本 Skill 的检查项。

不要把一次提交的偶然现象写成通用规律。

### 延伸动作

每个动作一行，至少包含：

- 动作：可执行的一句话。
- 类型：修复 / 测试 / 文档 / 工具 / 流程 / 架构。
- 优先级：P0–P3 或“可选”。
- 依据：对应发现或聚合结论。
- 验证方式：命令、测试或复核路径。
- 是否需要授权：是 / 否。

延伸动作只是候选；不自动修复、不自动提交、不自动开 PR。

### 覆盖与未验证

- 覆盖的提交、文件、目录与审查轴。
- 未覆盖的路径（例如未读的调用方、未运行的服务）。
- 未执行的验证及原因（缺环境、缺凭据、只读授权）。
- 明确区分“未发现问题”与“没有检查”。

## 大型窗口

- 提交数或 diff 规模超过一次可读范围时，按逻辑变更分批，并在报告中列出批次与未覆盖部分。
- 需要独立视角时，可派发只读子 Agent；给它范围、项目约定、diff 命令和输出格式，不给整个会话历史。
- 子 Agent 的结论仍是建议；主流程负责核对证据、去重和最终交付。
