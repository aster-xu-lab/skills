# AI 评测与成本治理

先定位 AI 调用链、模型与版本、真实流量、业务目标和现有观测手段，再设计评测与约束。不要默认项目使用某个模型厂商、评测框架、指标或部署形态。

本 Skill 管两件事：**怎么判断输出是否够好**，以及**怎么让成本与失败可控**。它不负责采集遥测本身，也不负责租户隔离的实现。

## 适用与不适用

适用：

- 为 LLM 功能建立离线评测集、基线、指标与回归门禁。
- 提示、模型、检索、工具或参数变更前后的效果对照。
- token 成本归因、租户/功能预算、配额与成本异常告警。
- 超时、限流、错误率或预算超限时的降级与回退策略。
- 审查已有 AI 功能的评测缺口与成本失控风险。

不适用：

- 只做 prompt 措辞优化、模型选型讨论，没有可核对的评测目标。
- 模型训练、微调、推理引擎调优。
- 单次 demo、人工试用或主观感受确认；这些不是评测。
- 普通业务接口的延迟与吞吐优化（走 `backend-engineering` / 性能诊断）。
- 替代 `ai-observability` 的采集接入，或 `multi-tenancy` 的隔离实现。

## 硬规则

1. **没有基线与样本，不声称“效果更好”**：先定义对照版本、数据集与指标，再比较。（来源：评测的基本对照原则；2026-11-19 画像中的 AI 工程化判据）
2. **样本可追溯**：评测样本留快照、版本与哈希；线上样本先脱敏，不把个人数据或业务密钥写入评测集。（来源：本库证据与隐私边界）
3. **指标对应业务目标**：任务成功率、结构化输出合法率、采纳率、人工修改率、延迟与每请求成本分开报告，不用单一准确率掩盖代价。（来源：LLM 输出非确定性与工程约束判断）
4. **任一变更都过门禁**：提示、模型、检索、工具、参数、依赖版本变化都触发回归对照；没有门禁的“优化”只是发布。（来源：把 LLM 放进工程约束的判据）
5. **成本可归因、预算有上限**：按租户、功能、模型和提示版本归因；硬上限与软告警分开，超限行为必须先定义。（来源：JVM 生态缺少开箱成本管控的判断；2026-11-19 用户画像）
6. **降级可观测、可恢复、有开关**：降级必须记录原因、影响范围与恢复条件；降级不能用“返回空结果”掩盖失败。（来源：降级回退的工程边界）
7. **单次运行不是评测**：样本量、随机性、模型版本和工具状态都要固定或记录；单次结果不足以推断稳定性。（来源：评测与调优方法）
8. **区分已验证与未验证**：静态设计、离线评测、真实流量验证分开报告；没有执行的部分明确标注。（来源：本库诚实汇报原则）

## 工作流

### 步骤 0：定位调用链与目标

1. 读项目约定与 AI 调用入口：请求从哪来、调用哪个模型、有没有检索、工具调用、缓存和异步队列。
2. 确认模型与 SDK 版本、温度/采样参数、提示模板来源、结构化输出约束。
3. 明确业务目标与失败代价：错答、漏答、越权、延迟、成本，各自由谁承担。
4. 找到已有观测与日志；没有时先说明缺口，不假装已有数据。

### 步骤 1：选评测类型并建样本

读取 `references/eval-design.md`。至少区分：

- **离线单元评测**：固定输入与期望，适合结构化输出、规则约束与回归。
- **版本回归评测**：同一数据集对照两个版本，看差异与显著性。
- **在线抽样评测**：真实流量抽样 + 人工复核，适合开放任务。

样本来源优先真实流量脱敏；不足时用合成样本并标注，不与真实样本混算。

### 步骤 2：定义指标与基线

固定指标口径：分母是什么、失败如何计、人工修改是否算成功、延迟按 P50 还是 P95、成本含不含重试与缓存。

基线至少记录：数据集哈希、模型与版本、提示版本、工具集、参数、运行时间。没有基线就没有“退化”判断。

### 步骤 3：接回归门禁

1. 选定必须阻断的指标与阈值；阈值来自业务可接受度，不凭感觉。
2. 变更前后各跑一次，同环境、同数据、同参数；记录失败样本而不是只记录通过率。
3. 门禁失败时区分：真实退化、样本漂移、环境差异、模型侧变更。原因不明时不放行。

### 步骤 4：成本与配额

读取 `references/cost-and-quota.md`。先建立归因，再设预算：

- 每请求、每功能、每租户的 token 与费用。
- 输入/输出/缓存 token 分开；重试与工具调用计入真实成本。
- 硬上限触发什么（拒绝、降级、排队），软告警发给谁。
- 配额与限流按租户隔离，不能靠全局总量掩盖单租户滥用。

### 步骤 5：降级与回退

读取 `references/degrade-and-rollback.md`。触发条件、降级层级、恢复条件和开关必须一起定义：

- 超时/错误率/限流/预算超限 → 小模型、规则、缓存、人工队列或明确失败。
- 提示、模型、索引与配置版本化，能一键回退。
- 回退恢复的是旧行为，不等于修复了根因。

### 步骤 6：交付证据

输出：评测范围、数据集与哈希、指标对照、门禁结果、成本归因口径、降级/回退验证、未覆盖项。区分离线结论与线上验证。

## 不做什么

- 不把 prompt 调优、模型榜单或主观体验当作评测结论。
- 不训练、微调模型，也不替目标项目选云厂商。
- 不替代 `ai-observability` 的指标采集与追踪接入。
- 不替代 `multi-tenancy` 的隔离实现；本 Skill 只定义配额与成本边界。
- 不把一次离线评测通过写成生产可用；发布仍需单独授权。
