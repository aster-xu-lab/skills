# 成本归因、预算与配额

本文件定义成本与配额的判断口径，不绑定计费平台或云厂商。价格与 token 口径以目标项目实际账单和 SDK 为准。

## 先归因，再设预算

没有归因的预算只会变成全局总额，无法回答“谁在花、花在哪、为什么涨”。最小归因维度：

| 维度 | 用途 |
| --- | --- |
| 租户/主体 | 隔离滥用、分摊成本、配额 |
| 功能/场景 | 判断哪个功能值得继续投入 |
| 模型/版本 | 比较模型切换的真实代价 |
| 提示/工具版本 | 定位变更导致的成本漂移 |
| 输入/输出/缓存 token | 区分上下文膨胀与生成膨胀 |

如果现有遥测只能拿到总量，先补归因字段；不要用总量估算代替归因结论。

## token 口径

1. 输入、输出、缓存读取、缓存写入分开统计；缓存命中率单独报告。
2. 重试、工具调用、多轮上下文重复计入真实成本，不只看首轮。
3. 截断、摘要、检索注入都会改变输入 token；提示变更要重新看成本。
4. 计费单位与四舍五入按供应商账单核对，不用本地估算替代对账。

## 预算分层

| 层级 | 作用 | 超限行为 |
| --- | --- | --- |
| 单请求上限 | 防单次异常消耗 | 截断、拒绝或转小模型 |
| 单用户/租户日预算 | 防滥用与失控 | 限流、降级、人工审批 |
| 功能月预算 | 控制产品线成本 | 告警、灰度收缩、停用实验 |
| 全局硬上限 | 防账单事故 | 熔断、进入只读/降级模式 |

硬上限与软告警必须分开：软告警用于提前干预，硬上限用于止损。硬上限触发后返回什么、由谁恢复，要提前定义。

## 配额与隔离

1. 配额按租户/主体隔离，不能只看全局总量。
2. 同时限制请求速率、并发数与 token 预算；只限 QPS 不限制长上下文仍会失控。
3. 配额拒绝要有明确错误语义和重试建议，不能返回空结果冒充成功。
4. 大租户与小租户共享模型时，记录各自的消耗，避免互相掩盖。
5. 配额与 `multi-tenancy` 的隔离实现配合：本文件定义边界，隔离实现由该 Skill 或项目负责。

## 降本手段与代价

| 手段 | 收益 | 代价/风险 |
| --- | --- | --- |
| 缓存相同请求 | 降低重复成本 | 结果过期、个性化失效、缓存键设计错误 |
| 小模型路由 | 降低单价 | 质量下降、路由误判 |
| 上下文截断/摘要 | 降低输入 token | 丢失关键信息、摘要偏差 |
| 批处理 | 摊薄开销 | 延迟上升、失败重试放大 |
| 结构化输出减少重试 | 降低失败成本 | Schema 约束可能降低召回 |
| 限制工具调用轮数 | 防失控 | 复杂任务提前失败 |

任何降本手段都要过评测门禁；不能只看账单下降。

## 成本异常

1. 监控日环比、租户环比、功能环比和单请求 P99。
2. 异常先区分：流量上涨、上下文膨胀、重试风暴、缓存失效、模型价格变化。
3. 重试风暴要同时看错误率和重试策略；只加预算不修重试会继续放大。
4. 成本告警要带归因维度，否则无法定位。

## 反模式

- 只有全局月度账单，没有租户/功能归因。
- 把缓存当成业务幂等或正确性保证。
- 硬上限触发后静默返回空结果。
- 用平均 token 估算容量，忽略长尾请求。
- 降本后不重跑质量评测。
- 把供应商价格写死在代码或文档里，不核对当前账单。
