# Spring AI / Java 服务接入点

本文件给结构位置，不替代目标项目的实际版本与 API 文档。Spring AI、LangChain4j 或自研客户端的类名、注解和配置键会随版本变化；执行前以项目依赖版本和官方文档为准。

## 先定位这些位置

| 位置 | 要找什么 |
| --- | --- |
| 客户端构造 | 模型、base URL、超时、重试、温度、最大 token 从哪来 |
| 请求入口 | Controller / 消费者 / 定时任务，谁触发 AI 调用 |
| 提示模板 | 模板文件、版本、变量注入点 |
| 检索 | 向量库、topK、过滤条件、索引版本 |
| 工具调用 | 工具注册、权限、超时、最大轮数 |
| 输出解析 | 结构化输出、Schema、失败回退 |
| 租户上下文 | 当前租户/主体如何传到调用链 |
| 观测 | 日志、指标、追踪、token 用量 |

没有观测时先说明缺口；不要凭日志猜测 token 与成本。

## 评测接入

在不改变业务代码路径的前提下，优先用统一拦截点记录：

- 请求哈希、提示/模板版本、模型与参数。
- 输入/输出 token、首 token 延迟、完整延迟、重试次数。
- 输出是否通过 Schema、是否触发降级、是否命中缓存。
- 租户/功能标识（脱敏后）。

记录内容足以复现一次评测即可；不要记录完整提示中的密钥、个人信息或业务敏感数据。

如果项目已有 Advisor、Filter、Interceptor 或 Observation 机制，按项目现有方式接入；没有时再新增最小包装，不重写调用链。

## 成本归因接入

1. 从客户端返回值或观测数据取 token 用量，不按字符数估算。
2. 把租户、功能、模型、提示版本作为维度写入指标或日志。
3. 缓存命中、重试、工具调用单独计数。
4. 价格从配置或账单导入，不写死在业务代码。

## 降级接入

1. 降级判断放在调用边界，不散落在业务逻辑里。
2. 开关从项目现有配置中心读取；没有时用最小配置项，并定义默认值与刷新方式。
3. 降级结果要与正常结果可区分，调用方能决定展示或重试。
4. 降级触发后记录原因与层级，便于恢复。

## 回归门禁接入

1. 用项目已有构建/测试命令运行评测脚本；没有时新增独立脚本，不混入单元测试主流程。
2. 评测脚本固定数据集、模型与参数；输出机器可读结果。
3. 门禁失败返回非零退出码，并保存失败样本清单。
4. CI 中的评测与真实调用分开授权；付费调用需要明确预算。

## 常见坑

- 只在聊天接口记录 token，漏掉工具调用和重试。
- 用字符数估算 token，导致预算偏差。
- 把租户 ID 写进日志明文，造成隔离信息泄漏。
- 降级开关读取失败时默认放开，放大风险。
- 评测脚本依赖本地模型或缓存，CI 中结果不可复现。
- 把 Spring AI 的默认重试与业务重试叠加，放大故障。
