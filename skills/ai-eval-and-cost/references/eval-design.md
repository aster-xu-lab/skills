# 评测集、基线与指标

本文件只写判据，不绑定评测框架。项目已有评测工具、数据集格式或标注流程时，以项目为准。

## 先选评测类型

| 类型 | 适合 | 不适合 |
| --- | --- | --- |
| 离线单元评测 | 结构化输出、字段约束、分类、抽取、规则边界 | 开放写作、多轮对话质量 |
| 版本回归评测 | 提示/模型/检索/工具变更前后对照 | 没有稳定数据集的探索期 |
| 在线抽样评测 | 真实流量分布、长尾与人工复核 | 高频全量、成本敏感场景 |
| 人工盲评 | 主观质量、语气、可用性 | 可自动断言的结构化任务 |

一个功能可以同时用多种类型，但**结论要分类型报告**，不能把离线通过写成线上可用。

## 样本设计

1. **来源分层**：真实流量脱敏样本、人工构造边界样本、历史缺陷回归样本分开存放，不混算指标。
2. **覆盖维度**：正常路径、空输入、超长输入、歧义输入、越权输入、工具失败、检索为空、模型拒答。
3. **标注一致**：多人标注时先定义判定口径；口径不一致的样本单列，不强行投票。
4. **金标准可追溯**：每条样本记录来源、标注人/规则、时间；样本变更要留版本。
5. **防泄漏**：评测样本不得来自生产密钥、个人信息或未授权业务数据；必要时脱敏后保留映射在外置安全位置。

最小可用评测集不是“越多越好”，而是**每个失败模式至少有一条能触发的样本**。

## 指标口径

先写分母，再写指标。常用指标：

| 指标 | 口径要点 |
| --- | --- |
| 任务成功率 | 什么算成功、部分成功如何计、超时算不算失败 |
| 结构化输出合法率 | JSON/XML/Schema 解析失败、字段缺失、类型错误分别计数 |
| 采纳率 | 人工接受/修改/拒绝的比例；修改幅度如何分级 |
| 人工修改率 | 修改字段数或编辑距离，避免只看“是否修改” |
| 延迟 | P50/P95/P99；区分首 token 与完整响应 |
| 每请求成本 | 输入/输出/缓存 token 分开，含重试与工具调用 |
| 降级触发率 | 按原因、租户、功能拆分 |
| 越权/注入拦截率 | 攻击样本被拒绝或安全降级的比例 |

**不要用一个综合分掩盖分项退化。** 综合分可以作为摘要，但门禁要看分项。

## 基线与对照

基线记录至少包含：

- 数据集路径与哈希、样本数、版本。
- 模型标识与版本、温度/采样参数、最大 token。
- 提示模板版本或哈希、检索索引版本、工具集版本。
- 运行环境、评测脚本版本、运行时间。

对照实验要求：同数据集、同参数、同环境；只改变一个变量。多变量同时变化时，结论只能写“组合变化”，不能归因到单个因素。

## 统计与稳定性

1. 记录样本量与失败样本清单，不只看通过率。
2. 有随机性的任务重复运行，报告波动范围；单次结果不写成稳定结论。
3. 差异接近阈值时，扩大样本或人工复核，不为了过门禁调阈值。
4. 模型侧静默更新、检索索引变化、依赖升级都视为变量，需要重新基线。

## 回归门禁

1. **阻断项**：安全、越权、结构化输出大面积失败、成本超预算、关键任务成功率下降超过阈值。
2. **告警项**：非关键指标小幅波动、长尾失败增加、延迟上升但未超限。
3. **人工放行**：只有记录理由、影响范围和复核人后才能放行；不能默认“先上线再看”。
4. 门禁失败先定位原因：真实退化、样本漂移、环境差异、模型变更。原因不明不放行。

## 反模式

- 用 demo 截图或一次人工试用代替评测集。
- 只测 happy path，没有空输入、超长、工具失败和越权样本。
- 训练集/评测集重叠，指标虚高。
- 只报平均分，不报失败分布和成本。
- 变更后不重跑基线，用旧结论解释新版本。
- 为了通过门禁修改样本或阈值，而不是修问题。
- 把离线评测通过写成“生产已验证”。

（来源：LLM 输出非确定性与工程约束判断；本库证据分级与评测方法）
