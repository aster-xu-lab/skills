# 行为评测与调优

按需用于验证本 Skill 的判断与执行，不在普通代码审查中加载。

## 固定任务与环境

- 路由评测提供职责相邻的候选，不预先指定本 Skill；显式读取入口不能证明自动选择正确。
- 执行评测在仓库外隔离目录完成，只向执行者提供 prompt、资产和完整原材料，不提供金标准、预期问题或上一轮结论。
- 用相同任务与夹具、同一宿主与模型比较无 Skill、当前版本和优化版本；资产提供方式不同的变体分别登记提示哈希。记录源哈希、环境、实际工具轨迹、耗时及可取得的用量；没有旧版本结果时不声称改善。
- 夹具需要的配置、测试和输入数据须列入用例 `files`。已有类型检查依赖缺失时报告前提，不自动安装。
- 每次运行保存 `inputs/` 与全部输入哈希，验收只使用该次快照。套件级哈希用于维护，运行级快照用于复现；两者不能互相替代。

## 必测决策

| 场景 | 核对行为 |
| --- | --- |
| 只读审查 | 无源码变更；问题可定位；没有虚构全库覆盖 |
| 明确授权重构 | 在指定范围实施，不重复等待确认；原行为与用户编辑保留 |
| 看似重复 | 比较单位、输出、错误与调用场景；允许不合并的结论 |
| 基线已有失败 | 比较具体失败，不自动归因本批或整文件回退 |
| 有保护条件或合理编排 | 核对反证，不因目录、行数或 I/O 与计算同处一函数就报缺陷 |

## 证据强度

审查结果中的严重度和路径只证明格式，不能证明发现成立。复核触发条件、影响、反证、建议归属与未覆盖项。只读用例用套件级 `protected_files` 表加 `protected_unchanged` 核对列出的受保护文件，用 `no_extra_files` 拒绝未声明的产物，并检查执行记录中的命令及越权操作；这些断言都不证明没有外部副作用。

已授权用例用行为测试核对成功、错误与副作用路径；`file_changed` 只证明目标文件发生了字节变化，不证明改对，具体结构由复核人依据 diff 判断。受保护表的哈希只覆盖不应改变的测试、配置和用户编辑。不靠函数名正则冒充重构成功。先做少量真实演练，出现不稳定判断后再重复同一用例，不以单次结果推断稳定性。

`write_scope` 将授权转成修改、创建与删除清单，其他原材料默认逐字保留。评测者显式执行 `review-behavior`，在新的隔离副本中复跑冻结命令，并核对实际退出码与失败原因；不能只采信执行者的报告。结果绑定完整 workspace 文件哈希，含获准新建的文件；任一产物再次修改、新增或删除后须重跑。

## 反例与判定分工

| 反例 | 自动检查 | 仍需复核 |
| --- | --- | --- |
| 只写报告未改源码 | `file_changed` 拒绝 | 无 |
| 越界修改、新增或删除 | `write_scope` 拒绝 | 外部副作用和完整工具轨迹 |
| 改坏行为却自报成功 | 评测者复跑测试并拒绝 | 未覆盖的运行语义 |
| 只加注释冒充重构 | 字节变化与行为检查可能通过 | diff 必须证明职责实际移出；此项判失败 |
| 准备后仓库或产物更新 | 冻结快照保持基线；旧行为记录失效 | 新版本重新进行对照 |

CLI 对照使用相同任务和原材料，比较无 Skill、旧版与当前版；至少记录客户端版本、可核实的模型、提示和源哈希、工具轨迹、改前改后行为与结构复核。每个宿主使用自己的既有认证与模型，不为跑通而改账号或猜模型。版本内的质量比较与跨宿主的兼容性分开报告；认证失败记为环境阻塞。临时显式读取源内容不等于全局安装或自动路由通过。

Codex 的隔离执行、JSONL 输出与非持久会话参数按 [官方非交互文档](https://developers.openai.com/codex/noninteractive/) 和当前客户端帮助核对。去除用户配置可能同时去除第三方服务商端点，不能把这种启动失败归因于 Skill；保留原服务商与模型设置，控制 hooks 与实际加载的资产，并记录残余全局上下文影响。
