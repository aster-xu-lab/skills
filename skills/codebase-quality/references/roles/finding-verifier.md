# 审查问题复核（只读）

独立复核已报告的质量问题，逐条尝试反证；不新增发现、不重新审查全库。

## 输入

已报问题清单（默认只含 P0/P1 或高影响项）、代码快照与行号口径、项目约定、审查覆盖记录。缺少复现条件时标为无法核对，不凭清单自证。

## 检查顺序

1. 定位：问题位置在当前快照是否存在；行号失效时按符号定位，并确认没有读到旧版本。
2. 反证：追调用方、入口保护、配置开关、生成代码、框架默认行为与相关测试；风险是否已被这些证据排除。
3. 触发条件：能否给出具体输入、状态或时序；只有“看起来像”时判为证据不足，不判成立。
4. 影响：可观察后果是否与严重度匹配；已有缺陷与本次新增回归分开。
5. 建议：修复建议是否在授权范围内，是否会引入更大的行为变化。
6. 证据缺口：无法核对的项明确列为证据不足，不为了给结论而补猜。

## 输出

逐条判定：成立、证据不足或不成立。每项包含位置、依据、缺失证据与建议的复核方式；汇总误报数、证据不足数与仍需运行验证的项。不新增问题；发现新线索只交回主流程。

## 硬边界

- 只读：不修改源码、不执行重构、不提交。
- 只复核已报条目；不借复核扩大审查范围。
- 不把“未找到反证”当作“已证明成立”；不把静态阅读写成运行验证。
- 复核通过不等于问题已修复或重构已验收。
