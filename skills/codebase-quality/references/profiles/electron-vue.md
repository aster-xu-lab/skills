# Electron + Vue 技术栈适配

本文件只写该技术栈下与质量审查、边界拆分和重构相关的通用判据，不绑定具体项目、路径或命令。项目事实以目标项目自己的约定为准。

## 一、进程与目录分层

典型分层：

| 层 | 职责 | 依赖方向 |
| --- | --- | --- |
| 主进程（main） | 窗口生命周期、系统能力、后台任务、持久化编排 | 可依赖共享层 |
| 预加载（preload） | 向渲染层暴露最小 API，转发 IPC | 只依赖共享契约 |
| 渲染层（renderer） | 界面、交互、视图状态 | 只依赖共享契约，不直接触碰系统能力 |
| 共享层（shared） | 类型、契约、纯函数、常量 | 不依赖以上任何一层 |

审查重点：

- 共享层是否反向依赖了某一进程层。
- 渲染层是否绕过 preload 直接访问系统能力。
- 主进程是否承载了本应属于视图的展示逻辑。
- 预加载是否暴露了超出实际使用范围的 API。

## 二、IPC 与契约

- 通道名、请求与响应类型应来自单一契约定义，不在两端各写一份。
- 每个暴露的 API 都应能回答：谁在用、为什么必须跨进程、失败时返回什么。
- 外部输入在进入可信边界前必须校验；不假定渲染层传来的数据可信。
- 错误应带有可区分的语义，不只返回 `null` 或空对象。
- 避免传输大对象或高频小消息；先确认是否真的需要跨进程。

## 三、状态所有权

- 同一份业务状态只允许一个进程持有真源。
- 主进程持有持久状态时，渲染层通过 IPC 提交变更；缓存或视图副本须明确同步、失效与版本规则，不成为独立权威写入源。
- 渲染层持有临时界面状态时，不回写主进程，除非有明确契约。
- 出现两端都能写同一份状态时，先确定真源，再迁移写路径。

## 四、主进程性能与阻塞

- 主进程里的同步 I/O、重计算和大循环会阻塞窗口事件循环。
- 长任务应可取消或可恢复，并明确资源释放路径。
- 批处理应分批让出事件循环，不一次性占用。
- 子进程或后台任务的失败路径要可见，不静默吞掉。

## 五、Vue 侧审查重点

- 默认使用组合式 API 与 `<script setup lang="ts">`；项目明确使用其他写法时遵循项目约定。
- 数据向下、事件向上；避免子组件直接改写父级状态。
- 组件复用优先抽取纯展示组件和组合式函数，不急于抽基类或高阶组件。
- 计算属性负责派生状态，不把可推导的状态重复存进响应式变量。
- 避免整包引入 UI 组件库；按需引入或复用项目已有组件。
- 模板中的表达式保持简单；复杂逻辑移到计算属性或组合式函数。
- 列表渲染确认稳定的 key；避免用索引作为可变列表的 key。

## 六、验证探测

不要硬编码命令。从项目配置中探测：

- `package.json` 的 scripts：类型检查、lint、构建、测试。
- 类型检查通常分为主进程 / 渲染层两套配置。
- 桌面应用还需要真机或启动后的手工路径；静态检查不能替代运行验证。
- 没有测试框架时，用类型检查、lint 和明确的手工验证清单作为基线，并说明其边界。

## 七、常见边界错误

| 现象 | 可能的边界问题 |
| --- | --- |
| 渲染层直接读写文件或调用系统 API | 缺少 preload 契约或契约过窄 |
| preload 暴露整个模块或通用调用器 | 暴露面过宽，应按用途收窄 |
| 主进程和渲染层各存一份业务数据，且无同步或版本规则 | 状态权威来源或副本一致性不清 |
| IPC 契约在两端重复定义 | 契约没有单一来源 |
| 主进程同步执行长任务 | 职责放错层或缺少异步设计 |
| 组件通过修改 props 或父级状态通信 | 违反单向数据流 |
