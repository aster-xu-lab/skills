# 安全重构手册

目标：在保持行为不变的前提下调整结构。功能变更不属于本流程。

## 一、动手前

1. 定义行为边界：输入、输出、副作用、错误行为、顺序和并发语义。
2. 确认验证手段：类型检查、lint、单元测试、集成测试、真机路径或手工清单；使用项目已有命令。
3. 记录基线：检查输出、具体失败项和环境；不能仅因失败数量相同就认定没有回归。
4. 记录 Git 状态及用户已有编辑，保存本批可恢复差异；当前 HEAD 不一定包含用户工作，不能直接当作回滚目标。

缺少验证手段时，先补最小验证或明确告知风险，不直接大改。

### 行为等价性

保持原有输入输出、错误类型与传播、副作用次数和顺序、事务边界、并发与取消语义。现有测试覆盖不足时，先补充描述当前可观察行为的测试，再在重构前后复跑；外部服务或真实环境不可用时明确未验证项，不用类型检查代替。

项目使用 Java/Spring 时尤其核对调用是否仍经过原代理、事务传播与回滚规则、异步租户上下文和资源释放；项目涉及 AI 调用时再核对重试幂等、预算扣减、审计失败和降级语义。这里只检查已有契约，不新增配置、框架或业务规则。

先看 Git 历史、调用方和相关 ADR，理解旧实现存在的兼容性或性能原因。测试以可观察行为为主；重构使内部测试布局变化时可以调整测试结构，但保留行为覆盖与期望。

抽取后检查是否无依据扩大了公共导出面；仅为测试内部函数而新增导出，不自动构成合理的外部接口设计，应结合任务和真实调用方复核。（来源：2026-11-13 隔离 CLI 对照中的公共导出差异；与既有接缝判据一致）

## 二、四种手法

### Extract

适用：函数或模块过长、职责混杂、局部逻辑可独立命名。

步骤：

1. 确认抽取部分的行为边界。
2. 抽出后保持调用顺序、错误传播和副作用不变。
3. 用同一套验证复验。

### Move ownership

适用：职责放错层、状态归属不清、跨层直连。

步骤：

1. 确认目标层与依赖方向。
2. 先建立新路径，再切换调用方。
3. 最后移除旧路径；不要一步删除。
4. 复验依赖方向和调用方行为。

### Inline

适用：抽象没有收益、只有一个调用方、转发层没有隐藏任何知识。

步骤：

1. 确认所有调用方都可修改。
2. 合并实现，保留原有错误与副作用语义。
3. 删除空壳后复验。

### Consolidate

适用：同一知识在多处重复，且已确认语义一致。

步骤：

1. 先用“三次规则”和“知识重复 vs 形状重复”确认该合并。
2. 选择最合适的归属位置，不默认新建工具目录。
3. 逐个替换调用方，每次替换后复验。
4. 保留必要的差异点作为参数或策略，不强行统一。

## 三、执行约束

- 一次只处理一个归属边界。
- 中间态必须可构建、可运行。
- 不夹带功能变更、格式化和无关文件修改。
- 不新增依赖或配置，除非是正确性必需且已获确认。
- 每批完成后运行基线及必要的补充验证；失败先与原输出比较，定位为新增回归、既有失败或环境故障。原因不明时停止叠加并保存证据。
- 明确由本批引入的回归，在授权范围内修复或撤销本批差异；无法与用户编辑安全分离时保留工作树并报告，不执行整文件恢复、reset 或清理来回退。

## 四、验收

| 检查 | 要求 |
| --- | --- |
| 行为 | 与重构前一致；差异必须有明确证据 |
| 边界 | 依赖方向、状态所有权符合目标结构 |
| 验证 | 原检查继续执行，补充检查在改前改后运行；记录未覆盖行为 |
| 范围 | 只包含已确认的候选，无顺带改动 |
| 回退 | 每批可独立回退 |

## 五、停止条件

出现以下情况时停止并报告，不继续叠加：

- 验证失败且原因不明。
- 影响面超出候选声明。
- 需求实际包含功能变更。
- 发现 P0 级问题。
- 改动需要新的依赖、权限或外部环境。
