# 质量审查判据

本文件只写通用判据，不绑定语言、框架或目录。项目专属事实由对应 `profiles/` 文件补充。

## 审查轴

| 轴 | 看什么 | 常见证据 |
| --- | --- | --- |
| 正确性 | 错误处理、异步竞态、边界输入、空值、状态迁移 | 未捕获的拒绝、未校验的外部输入、竞态时序 |
| 可读性 | 命名、函数长度、嵌套层级、注释是否解释“为什么” | 超过一屏的函数、三层以上条件嵌套、复述代码的注释 |
| 架构 | 依赖方向、职责单一、状态所有权 | 反向依赖、同一状态多处可写、跨层直连 |
| 安全 | 外部输入、最小暴露面、沙箱、凭据边界 | 未过滤的输入、过宽的导出面、日志中的敏感值 |
| 性能 | 主线程阻塞、大对象跨边界、重复计算 | 同步重计算、跨进程传输大对象、循环内重复查询 |
| 复用 | 重复是否属于同一知识、是否已有现成能力 | 复制粘贴的实现、重复的类型定义、绕开已有工具 |
| 边界 | 模块深度、接缝位置、可测试性 | 浅模块、无法在不启动完整运行时测试核心逻辑 |

## 严重度

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| P0 | 影响广泛且触发确定的严重数据丢失、安全破坏或不可恢复损害 | 立即停止重构，先报告 |
| P1 | 高影响的正确性、安全缺陷或高风险边界错误 | 优先修复，单独验证 |
| P2 | 可维护性问题：重复、职责混杂、浅模块 | 进入重构候选，排序后处理 |
| P3 | 风格、命名、局部可读性建议 | 不单独重构，随相关改动处理 |

## 证据要求

- 每条问题必须能定位到 `文件:行`，或给出可复现命令与输出。
- 只有推断、没有证据时标为“待确认”，不写成结论。
- 不把“看起来像”当作问题；不为了凑数列风格偏好。
- 报告前追到实际调用方、入口保护与相关测试；这些证据排除风险时撤销问题。函数长度、同步调用或目录位置只是线索，不直接决定严重度。
- 每条缺陷说明触发条件、可观察后果和证据限制；已有缺陷与本次新增回归分开标注，影响程度与证据可信程度分开表达。没有已确认问题也是有效结果。
- 遵循项目已有设计决策；候选与 ADR 冲突时标明冲突及重新讨论的实际依据，不重复提出已被约束排除的方案。

## 覆盖记录

每批记录已读模块、关键入口及调用链、使用的检查、未覆盖路径与原因。跨模块问题必须追到契约与调用方，不能仅按目录分批后各自判定。全库未覆盖时明确交付为局部审查。

## 通用反模式

以下现象只作为线索，是否成立要结合上下文确认：

- 同一个知识在多个地方以不同形状重复。
- 一个函数同时做编排、计算和 I/O。
- 底层模块反向依赖上层模块。
- 模块接口很宽，但实现很浅，调用方需要了解内部细节。
- 为了复用而抽出的抽象，只被一个调用方使用，且没有收敛变化。
- 错误被吞掉，或异常只在最外层统一处理而丢失上下文。
- 状态有多个可写入口，没有单一所有权。
- 测试必须启动完整运行时才能覆盖核心逻辑。

