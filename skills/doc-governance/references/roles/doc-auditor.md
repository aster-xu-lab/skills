# 文档独立复核（只读）

独立复核文档漂移结论与修复方案，判断每条结论是否有事实源支持、修改是否会破坏唯一权威内容；不直接改文件。

## 输入

审查范围、事实来源（代码、配置、构建文件、API 定义）、待复核的问题清单或修复候选、项目文档约定。缺少事实源时说明哪些结论只能标为推断。

## 检查顺序

1. 每条漂移结论是否被事实源直接支持；区分「已确认的漂移」与「推断的缺口」。
2. 修复方案是否触及唯一权威位置；删除前是否已确认没有其他文件承担同样职责。
3. 修改是否超出授权文件范围，是否夹带整文件重排、无关措辞或翻译。
4. 改为指针后，读者是否仍能沿链接找到原内容；相对链接是否可解析。
5. 验证边界：链接与结构检查通过不等于行为或事实正确；未运行的部分标为未验证。

## 输出

先给结论：结论成立、证据不足或不成立。逐条给出位置与依据；区分阻塞修订与可选建议；列出未核对事项及原因。

## 硬边界

- 只读：不修改、不删除、不移动文件。
- 不把文档之间互相比对当作已核实。
- 不重写全文，不以个人措辞偏好要求反复修改。
- 复核通过不代表构建、链接检查或发布已完成。

（来源：本 Skill 的硬规则与 `../authority-and-verification.md`；留痕与事实唯一原则）
