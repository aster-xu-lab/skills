# 检查清单

三类检查按优先级排列：漂移（必查）→ 指针完整性（必查）→ 冗余与精简（建议）。每类给出判据与常见形态；标注「通用」的条目来自跨项目复用，标注项目来源的条目只作示例，不要硬套。

## 一、漂移检查（必查）

| # | 检查项 | 判据 | 常见形态 |
| --- | --- | --- | --- |
| 1 | 同一事实多处不一致 | 版本号、日期、数量、状态、路径在 A 写一套、B 写另一套 | README 写 `0.5.2`，`package.json` 与指南写 `0.6.2` |
| 2 | 旧判断未标注修正 | 旧结论仍在正文，新结论只出现在别处 | 旧文写「不支持 X」，实现已经支持 |
| 3 | 引用失效 | 指向已改、已删或已合并的章节 | 文档写「部署说明见 deploy.md」，该文件不存在 |
| 4 | 标题与条目数不符 | 标题写「三条方针」，正文只剩两条 | 精简时删条未改标题 |
| 5 | 快照日期滞后 | 文档声明的维护日期早于最后实际更新 | 索引写 10-13，内容已改到 11-13 |
| 6 | 待办已闭环未关闭 | 勾选状态与正文证据矛盾 | `- [ ] 支持批量导入`，下一行写「已在 11-01 上线」 |
| 7 | 策略变更未回写 | 一处改了决策，其他入口仍是旧策略 | 方案改为 A 策略，README 仍写「必须进第一档」 |
| 8 | 文档声明与代码不符 | 命令、参数、默认值、字段名与实现不一致 | 文档写 `npm run check`，`package.json` 里没有该脚本 |
| 9 | 外部事实过期 | 费用、配额、线上状态等易变信息未标日期 | 报价表无更新时间 |

判据来源：个人文档治理实践与工程仓库文档治理约定。第 8、9 项为跨项目补充。

## 二、指针完整性（必查）

| # | 检查项 |
| --- | --- |
| 1 | 文档索引覆盖所有现行文件，含新增文件 |
| 2 | 每份现行文档在索引中有明确职责说明 |
| 3 | 交叉引用指向的章节或锚点仍然存在 |
| 4 | 仓库外资料按名称引用并标注「仓库外」，不写越仓相对链接 |
| 5 | 已废弃或已迁移的文件标注去向与替代入口 |
| 6 | 生成文件的来源、生成命令与未重新生成的残余风险写明 |

来源：个人文档治理实践与通用文档维护要求。

## 三、冗余检查（建议）

| # | 检查项 | 判据 |
| --- | --- | --- |
| 1 | 同一理由重复 | 同一条论据在同一文件出现多次 |
| 2 | 同一结论跨文件复述 | A 写完整推理，B 又写一遍；应改为指针 |
| 3 | 同日变更记录重叠 | 同一天多条可合并的条目 |
| 4 | 细节超出读者需要 | 字段名、代码级实现、单表行数写进画像类文档 |
| 5 | 选项集与既定计划混写 | 同一文件既说「方向未定」又给「唯一动作」 |
| 6 | 宿主入口复制正文 | `.claude/`、`.cursor/` 等入口重复维护规则正文而非指向共享源 |
| 7 | 迁移残留 | 旧平台、旧命名的说明只改了一半 |

来源：个人文档治理实践与工程仓库文档治理约定。

## 四、精简判据

| 动作 | 保留 | 删除或压缩 |
| --- | --- | --- |
| 删 | 结论、可追溯性、决策留痕 | 字段级细节、重复推理、无信息量的过渡句 |
| 压 | 一张结论表加指针 | 多段论证、代码级核查过程 |
| 不动 | 已推翻但标注了「已修正」的旧判断 | — |

来源：个人文档治理实践。

## 五、严重度

| 级别 | 定义 |
| --- | --- |
| P0 | 事实互相矛盾，会误导执行或决策 |
| P1 | 引用失效、索引缺失，导致找不到或找错材料 |
| P2 | 重复内容显著增加维护成本 |
| P3 | 风格、格式、可读性，不影响事实 |

没有真实来源可对照的条目放在「待确认」，不混入结论。
